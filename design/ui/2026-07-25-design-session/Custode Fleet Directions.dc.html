3Missions & crews — and custode as root
my answer to the team question

You’re stuck because you’re asking “does each teammate get a panel?” — and the answer is no, but only because the panel shouldn’t belong to the agent in the first place. It should belong to the mission: the repo, the watch, the domain. That’s the thing you actually care about and the thing that has a stable name.

custode→ mission(mdbook‑lint)→ crew member(@triage)→ item(#400)
  • A mission has a crew, and attention rolls up. The fleet shows missions. When something needs you it says which crew member raised it, but you never had to know the crew existed to see it.
  • Individually addressable without individually navigable. Every agent gets a handle — @lead, @triage, @analyst — scoped to its mission. You address them in the composer; you don’t visit them at a URL. An agent expands into a lane on the mission page, it isn’t its own page.

1Fleet page — four directions
my read

The tile grid answers “what exists”, but your actual job is “what needs me”. Today every agent is drawn at the same weight and the same size, so a red check on mdbook-lint looks exactly as loud as stars being pleasantly idle. At 16 agents you can scan past that. At 50 you can’t.

The tile is also carrying eight jobs at once — identity, worker type, cron, tags, spend, sparkline, todo count, next beat, latest event. Most of those are reference data, not scan data. They belong on the agent page.

so the system these share
  • One derived signal per agent. Every agent resolves to exactly one state: needs you (approval, red check, budget rail, stuck gate) → working → scheduled → quiet. That’s the sort key, not recency. Recency is a tiebreaker.
  • Attention earns pixels. Agents that need you get a full row with the reason spelled out and a resolving action inline. Quiet agents collapse to a name.
  • Active vs. catalog. Your “page and a half” instinct is the right one — a small working set you curate, and a full catalog you visit deliberately.
  • Three levels, consistent. fleet → agent → item (issue / PR / turn / gate). Same chrome at each level, so drilling down never feels like a different app.
  • Mono for identifiers and numbers, sans for interface. Keeps the terminal DNA where it means something and stops the whole page from reading as a log dump.
  • Spend is secondary for you, primary for someone else. Ships as one toggle rather than two designs (see the Tweaks panel).

On the feed: I think it isn’t useful because it’s a firehose of events with no notion of “since I last looked”. The while you were away digest is the good version of the feed — below I treat it as a first-class surface and let the raw feed become a per-agent tab.
